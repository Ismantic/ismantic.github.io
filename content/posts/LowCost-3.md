还是由低成本说起，用语言模型驱动做机器翻译的好处是对平行语料的数量的要求大大减少了，以及通过强化学习还能让翻译效果得到提升，这两步都是必须的。但是预训练，不得不说成本还是太高了。Qwen3的预训练用了119个语言总共36T Token，这个量级实在是够高了，训练成本也可想而知，实在是说不上是低成本了。

对预训练我的理解，万变不离其宗，它就还是个语言模型，根据上文，按照语料分布，预测下文，这个按说就是本质了。有不少工作去更量化的分析模型参数数量和语料Token数量的关系，该怎么配比更合适，其实有一点是很难说清楚的，那就是语料的质量和分布。这可能也是很多工作还能脱颖而出的原因。回到这个低成本实践这个工作，借助Qwen3已经开源出来的底座模型，已经训练出来了一个不错的模型，那么接下来呢。

当然该去做看看怎么搞语料去训练一个底座模型，最好能超过Qwen3，不过这个难度很大，也许以后会试试。但Qwen3也不是完全没有动手的地方了。首先，因为Qwen3用了119个语言，而我们这个项目只用中英的话，其实Qwen3的Tokenizer是冗余的，其一是词表过大，这样就有点浪费，其二是中英文比重可能也不够好，就效率上也还有改进点。Qwen3没有公布其的Tokenizer的训练方法，而SentencePiece的话，针对中文其实还有两个弊端，一是没有对中文预切词，这会导致学到很多很长的词，二是把中文和英文同等对待，会导致学到很多空格开头的词。

LLama 时代的时候，因为其只用英文语料，Tokenizer 的词表也就只有英文词和很少的中文，就有一系列的工作给 LLama 模型扩充词表，光改词表还不行，还要给中文词对应的Embedding赋予权重，再以及模型见过的中文少，也需要把模型再训练下，但不能损伤模型原有的能力。这样的工作就叫ReTok。具体来说，大概是三个步骤，对新Tokenizer的词的参数初始化，一般就是用老Tokenizer对新词切分，然后用老词的参数的平均值给新词。第二个步骤是冻住词表以外其它参赛，用50%类似老语料的分布和50%新增语言的分布训练。第三步，再全量参数训练。

ReTok 其实主要是对底座模型的改造，其实我也尝试过对HY-MT模型做ReTok，但效果不好，我就不放试验结果了。而且搞ReTok其实也是对预训练的一次实践，也是需要看训练效果对各个下游任务的影响的，更进一步说，CPT其实做的也挺多的。HY-MT其实就做了不少CPT

| Stage | Zh→En BLEU / COMET | En→Zh BLEU / COMET |
|---|---|---|
| ReTok-Base (5-shot) | 17.44 / 0.7582 | 38.10 / 0.8255 |
| SFT | 19.34 / 0.7762 | 40.09 / 0.8392 |
| CPO | 18.11 / 0.7941 | 31.38 / 0.8480 |
| **GRPO (This Model)** | 18.43 / **0.7967** | 31.79 / **0.8511** |
| HY-MT1.5-1.8B (Reference) | 17.84 / 0.8052 | 31.74 / 0.8669 |

实验结果见上表，由FewShot来看，这个底座模型不大好，但是SFT/CPO/GRPO三个步骤还是把翻译效果提升上来了，虽然比不上前面那个不做ReTok的翻译模型，更比不上HY-MT了。收获还是有的，就是证明了，可能底座模型其实差一点，也还是能通过后训练把能力进一步提升的，那么也许还是可以尝试做一个预训练模型，只要过了一个基本的门槛，通过后训练来把效果提上去。
