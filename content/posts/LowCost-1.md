根据我的理解，机器翻译已经到了第三代，第一代是统计时代，基本的做法是对 `P(T|S) = P(S|T)*P(T)` 这个式子的拆解，其中P(T)部分基本就是多元语言模型，也就是最多统计几个Token的共现次数，P(S|T)是根据双语词典或者双语平行语料挖掘出来的Phrase Pair，比如 `<红色, Red>` 这样。这套方法缺点蛮多的，比如需要意译的时候，很多Phrase Pair就很难挖掘了。这套方法我没有实践过，而且能感知到Phrase Pair的挖掘会有很多技巧和难点，到了现在这套方法用来做机器翻译应该已经抛弃了，但是输入法上我认为还是有价值的，比较关键的是P(S|T)这个步骤有明确的规则，没那么多难以言说的点。

到了第二代，实际上就是RNN和Transformer了，是Seq2Seq那篇论文开启的。以及还有很多改进工作其实后面都成了大语言模型技术的基础，除了Transformer还是有Subword这样的BPE等算法，虽然很简单，但是基本上彻底解决了OOV问题，让语料和参数完成了闭环。这代技术唯一的缺陷是不能泛化，这里的泛化是说这个模型这些语料只能训练翻译模型，而且需要海量的双语平行语料，对平行语料的挖掘，有用电影字幕的，有挖掘维基百科同词条不同语种的平行句对的，还有一些标准的语料，比如联合国发言什么的。这代方法，我也只是在个人学习的时候去了解和简单实践下，也就是写写模型结构，找些平行语料跑下，也没做出什么好的结果。

其实挺遗憾的，第一代的时候我应该是在搞LDA，第二代的时候也就是搞了搞W2V，后期沾光做了些BERT，因为这些技术对实际应用结合性更好些，而机器翻译一直是偏Research的，技术又不够成熟，难以取代人工，即使能取代，相比信息流推荐和搜索来说，翻译的市场也实在太小了。当然市场大小其实跟我也没有关系，但我当时一是也不会这些，二也是确实没机会去做这些技术。其实我一直挺羡慕当时Lab部门的，可我大学到博士毕业，也似乎不是好的科研苗子。

第三代就是大语言模型时代了，到这代其实全部技术都来自于第二代，只是方法变了。第二代的时候可以理解是训练P(T|S)，但第三代说只要训练P(T,S)就够了。而且也不是训练Transformer这样的Encoder+Decoder，而是只训练Decoder就可以了，而GPT基本成为了Transformer Decoder的代名词。GPT-3的时候，提出了一个概念叫 In Context Few Shot Learner，就是说只要找到海量语料按照Next Token Prediction的方式训练好了GPT，那么对训练好的模型，把Few Shot喂给模型，比如 S1 -> T1, S2 -> T2, S3 -> T3，再紧接着给模型 S4 -> ，它就会吐出 T4 ！，这个现象真的很神奇，当时论文中说也许语料中存在这样的双语平行句对的数据，模型学会了这个Pattern，因而就能预测T4了。不过我后来也查过一些资料，可能这个解释是不成立的，到现在，我其实也没搞明白为什么模型可能泛化出这样的能力。

Few Shot 效果相比 Seq2Seq 那种方式是实打实的提升，就是用起来不方便，而且每想做一个任务都要先给几个Example也不现实，因而后训练技术（相比训练大语言模型叫预训练）就也发展出来，第一步是SFT，其实类似把各个任务的Few Shot结合一些Prompt丢给模型去训练，这样给模型再交代任务的时候就不用先说几个例子了，但问题是发现这么训练之后模型的泛化能力会下降，这个是为什么其实我也不明白。第二步是RL，因为SFT会造成模型能力下降，就引入强化学习来继续提升模型的能力，基本思想大概是对模型的回答，正确的给予奖励，错误的给予惩罚。当然这些训练技术不只是翻译一个任务的，而是把GPT当成了一个全能模型，只要是能通过吐出Token来完成的任务，都可以丢过去训练。

说回到翻译，SFT+RL这样的方法其实也可以只用来训练机器翻译模型，这样机器翻译模型可以分成两步，第一步还是训练P(S,T)，也就是Next Token Prediction任务的语言模型，第二步是SFT+RL，让语言模型能响应翻译任务，且能通过RL把SFT对能力的损失找回来或者进一步提高。其实我还有疑惑，这样就是针对机器翻译训练最佳的方法了吗，第二步我觉得比较好理解了，但第一步训练该怎么做才是最合适的，因为这一步还是消耗了太多资源。因而，我想实践下，用最低的计算成本（消费级显卡），来看看能实践出怎样的机器翻译效果了。

这是我要写的一系列文章的第一篇，接下来我想尽可能以低成本的方式以机器翻译这个任务，把大语言模型相关的技术探索一遍，包括后训练技术，预训练技术，以及不来虚的，要交付出可以实际使用的接近SOTA的中英双语翻译模型。不过我很怀疑自己做这个项目的意义，现在大语言模型写代码写文章的能力是超过我的，甚至用户需求也更多的去找大语言模型了，写技术文章也似乎意义不大了，那我为什么还做这个呢？是需要给自己一个交代吗，弥补当年没有做过机器翻译的遗憾，去探求做大语言模型的技术细节吗，还是只是修炼自己，不认输不放弃，可又说回来机器根本不存在这样的问题，机器天然就能Loop下去。最后我想的是，人还是有非理性的一面，也许这才是机器做不到的。也许这样才能做一些明明不可能不合适的事情。
